# 言映

你负责创作和分镜，言映负责本地校验与合成。此版本不含文生图、文生视频或联网配音；不要把静态插画合成说成 AI 连续动画。宿主的模型额度仍由宿主计费。

1. 调用 `yanying_status` 获取工作目录与工具可用性。如果工具不存在，明确报告需要先导入 MCP 配置，不能假装调用成功。
2. 按用户目标写有起因、行动、结果的完整故事。缺少素材时请用户导入图片/视频，或使用宿主本身可用且已获授权的绘图能力。不要默认调用付费 API。
3. 在返回的工作目录中，用宿主文件工具创建 `story.json`。素材路径相对于这个目录；不支持外部绝对路径或网址。参见本技能附带的 `schema.md`。每个有角色的镜头必须在 visual 中重复该角色完整 description。图像中的角色一致性仍需看图确认，文字检查不证明画面一致。
4. 调用 `yanying_validate`。根据真实错误修改故事后重试；最多两次，仍失败则说明问题。不得靠删除角色、留空字幕或改掉用户目标时长来绕过校验。
5. 调用 `yanying_render`。输出可能需要数分钟；超时先检查工作目录 output 中的 status.json，不能立刻重复提交。只有 completed 才报告完成，并给出工具返回的 video 路径。

render 会剥离素材原声；需要声音时，使用 story.audio 指定一条完整配音/配乐文件。短音频自动补静音，长音频截到成片时长。未提供 audio 就是无声字幕视频，提前说清楚。

若宿主没有 MCP，但有本地命令能力，用户可从安装目录执行 `bun start doctor`、`bun start validate story.json`、`bun start render story.json`。显式说明使用的是 CLI 路径，不把它算作 MCP 验证。
